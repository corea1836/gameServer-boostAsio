- 틱 p50이 봇 50에서 14.8~15.9 → 0.32~0.34ms, 봇 200에서 220~226 → 4.0~4.2ms로 줄었다. 100명부터 놓치던 데드라인이 200명까지 0이고, 틱이 초당 20번 다 돈다.
- 쓰기 1번당 패킷이 1.00~1.05 → 22~38이 됐다. `Send`가 push와 (배치당) post만 하게 되면서, `_isWriting`이 서 있는 동안(post부터 `Write` 실행까지의 strand 대기 + 앞 쓰기가 끝날 때까지) 들어온 패킷이 `_sendQueue`에 쌓였다가 `Write` 한 번에 같이 나간다. 한 틱의 송신이 쓰기 한 번으로 다 묶이지는 않는다. 표에서 계산하면 세션당 틱당 쓰기는 봇 50에서 약 2번(초당 35~41번), 100에서 약 3번(59~64번), 200에서 약 5~6번(95~126번)이다. strand가 의도한 배칭은 아니고, `Send`가 빨라져 배칭 창 안에 여러 패킷이 들어오게 된 결과다(ADR-008 트레이드오프).

- 바이트는 그대로 N²이다. 봇 200의 세션당 송신은 155~161KB/s(전체 약 31MB/s)이고, 전에는 틱이 초당 4번만 돌아서 31~32KB/s로 보였을 뿐이다. AOI(R4)가 줄일 것은 이 바이트다.
- 봇 200의 틱 p99가 구간에 따라 7~37ms로 흔들린다. 원인은 아직 보지 않았다.

- "전"에 1건 나오던 asio reactor 내부 경고(`kqueue_reactor::run`이 `conditionally_enabled_mutex::enabled_`를 락 없이 읽음)는 이번 120초 실행에서는 나오지 않았고, strand 적용 뒤 봇 3개 실행에서는 1건 나왔다. asio 소스(`kqueue_reactor.ipp:494`)를 보면 accept 스레드가 만든 descriptor_state를 network 스레드가 kevent가 돌려준 포인터로 읽고, 둘 사이의 순서는 커널만 보장한다. TSan이 볼 수 없는 순서라 오탐으로 본다.

- 평균 가시 인원 = (봇 전체 `spawned` − `despawned`) ÷ 봇 수. 봇 로그의 5초 간격 값이다.
- **봇이 계속 퍼진다.** 흩어진 뒤의 랜덤 이동에 경계가 없어서 측정 구간 동안 밀도가 계속 낮아지고, 평균 가시 인원과 송신량이 함께 줄었다(봇 200의 세션당 송신은 구간 순서대로 25.3 → 16.8KB/s). 표의 범위는 밀도가 고정된 조건의 흔들림이 아니다.
- 봇 200 전 → 후: 세션당 송신 155.4~158.7 → 16.8~25.3KB/s(84~89% 감소), 송신 패킷 717k~728k → 77k~117k/s, 서버 CPU 51~56% → 23~28%, 틱 p50 5.2~5.8 → 2.7~3.8ms. 이때 평균 가시 인원은 199명 → 31~19명이다.
- 세션당 송신 ÷ 가시 인원은 전(158 ÷ 199)과 후(25.3 ÷ 31, 16.8 ÷ 19) 모두 약 0.8~0.9KB/s다. 송신은 보이는 인원에 비례하고, AOI가 줄인 것은 N이 아니라 "보이는 사람 수"다.
- 틱 시간이 줄어든 것은 `Send` 호출이 줄었기 때문으로 보인다. 거리 비교(봇 200이면 틱당 약 4만 번)의 비용은 따로 재지 않았다.
- 시작 직후(5초)에는 모두 (0,0)에 있어서 서로를 다 받고(`spawned` ≈ N × (N−1)), 흩어지면서 despawn된다. 측정 구간에서 봇 1명이 받은 spawn + despawn은 초당 약 6건(봇 200)이다. margin 0과 비교하지 않아서 히스테리시스가 이 수를 얼마나 줄였는지는 아직 모른다.

## M3 클라 예측 + 정지 후 보정 시연 (2026-10-22, ADR-023)

**목적**: 지원 마감(2026-10-23) 전에, 지연이 있을 때 내 캐릭터 반응이 예측 전후로 어떻게 달라지는지 화면 녹화로 남긴다. 정식 보정(4단계 seq/ack + 재시뮬레이션)은 뒤로 미루고, 그 전에 proto와 서버를 바꾸지 않는 최소한의 보정만 넣었다.

**상황**
- 서버 `1c757d5` + 작업 트리(AOI 1단계), 클라 `bb71884` + 작업 트리. 클라만 바꿨다(`SelectedPlayer.cs`, `InputLatencyProbe.cs`, `Actor.PushMovePkt`). 서버 이동은 그대로 `방향 × 속도 × dt`이고, 클라가 같은 식으로 예측한다
- F3로 Off(내 최신 `S_Move`를 버퍼 없이 그림) → Predict(보정 없음) → PredictCorrect(멈추고 0.5초 뒤 서버도 멈춰 있으면 맞춤)를 바꾸고, F1/F2로 지연 시뮬레이터 조건을 바꾼다. 원격 캐릭터를 같이 보려고 봇 50(`DummyClient 50`)을 붙였다
- 동작 확인(Unity `Editor.log`, 지연 150±0ms, 조건마다 표본 1~4개): 출발 반응은 Off 350~383ms, 예측 모드 0ms(키를 누른 프레임에 바로 움직임). 정지 오차는 Predict 0.345, PredictCorrect 0.08~0.27. 표본이 적어서 수치 주장에는 쓰지 않는다
